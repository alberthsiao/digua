# 陳地瓜走到哪 R1.8

陳地瓜徒步環島的打卡與通知系統。

前端靜態網頁（GitHub Pages）＋ 後端 Google Apps Script（試算表、Drive、寄信）。

```
web/  → 丟到 GitHub Pages / Cloudflare Pages
  index.html      公開地圖＋日記，任何人都能看
  digua.png / og.jpg / icon-*.png   頭像、分享預覽圖、PWA 圖示（與 html 同層，不放子資料夾）
  checkin.html    打卡頁，網址帶通行碼，只給環島的朋友
  subscribe.html  訂閱與退訂
  manifest.json / sw.js / icons/   加到主畫面用

gas/
  程式碼.gs        貼進 Apps Script
```

## 為什麼前端不放在 Apps Script 裡

Apps Script 的網頁應用程式是包在跨網域 iframe 裡送出來的，而 `navigator.geolocation` 在跨網域 iframe 需要外層加上 `allow="geolocation"`——那個 iframe 是 Google 產生的，我們改不到。這個限制自 Chrome 63 起生效，Google 的功能請求（issue 68032861）至今未實作。

所以定位頁必須是頂層文件。順帶好處：可以裝 Service Worker、可以做 PWA、可以綁自己的網域。Apps Script 專心當 API 就好。

## 一、後端（約 10 分鐘）

1. 用**專門開的那個 Google 帳號**建一個新試算表，命名「陳地瓜走到哪」。
2. 選單 **擴充功能 → Apps Script**，把 `gas/程式碼.gs` 全部貼進去，覆蓋原本的內容。
3. 改最上面的 `CONFIG`：

   | 欄位 | 說明 |
   |---|---|
   | `CHECKIN_TOKEN` | 一組長亂碼，等一下會出現在打卡頁網址列 |
   | `SITE_URL` | 前端網址，**結尾不要斜線** |
   | `WALKER_NAME` | 已填「陳地瓜」 |
   | `SITE_NAME` | 已填「陳地瓜走到哪」，寄件者名稱與信件抬頭都用它 |
   | `START_DATE` | 出發日，用來算「第幾天」 |

4. 執行一次 `setup()`，授權所有權限（會要求 Drive、Gmail、地圖）。這一步會建好兩個分頁和照片資料夾。
5. 執行一次 `testMail()`，確認信寄得出去。
6. **部署 → 新增部署作業 → 網頁應用程式**
   - 執行身分：**我**
   - 誰可以存取：**所有人**
   - 複製出來的 `.../exec` 網址。
7. 之後每次改 `程式碼.gs`，都要**部署 → 管理部署作業 → 編輯 → 版本選「新版本」**，不然線上跑的還是舊的。

## 二、前端（約 5 分鐘）

1. 把 `web/` 三個 html 檔最上面的 `API_URL` 換成剛剛那個 `.../exec` 網址。
2. `checkin.html` 裡的 `START` 出發日要跟後端 `CONFIG.START_DATE` 一致。
3. 建一個 GitHub repo，把 `web/` 底下的東西放進去（注意是內容，不是資料夾本身），Settings → Pages → 來源選 main 分支根目錄。
4. 記得回頭把後端的 `SITE_URL` 改成實際網址，重新部署新版本。

## 三、交給環島的朋友

傳這個網址給地瓜，只傳給他一個人：

```
https://你的網域/checkin.html?t=你設定的CHECKIN_TOKEN
```

請他用 Safari 或 Chrome 開啟，**加入主畫面**。通行碼會存在裝置裡，之後從主畫面點開就直接能打卡。

第一次按任何一顆按鈕時，手機會問要不要允許定位——一定要選「允許」。

三顆按鈕：

| 按鈕 | 會寄信嗎 | 什麼時候按 |
|---|---|---|
| 出發 | 所有訂閱者 | 早上上路，開始計時。可以設定今天的目標地點 |
| 打卡 | 只有選「每次打卡都要」的人 | 路上拍照寫短句，一次最多 8 張 |
| 收工 | 所有訂閱者 | 今天走完了，留言欄那段就是當天日記 |
| 今天休息 | 所有訂閱者 | 今天不走。不計時、不算里程，但照樣可以打卡拍照 |

當天第二次以後按「出發」會被視為「繼續走」，只寄給選「每次打卡都要」的人。

訂閱時可選兩種：**每次打卡都要**（一天五到十封，預設）或**出發和收工就好**（一天兩封）。沒有每日摘要信，想看細節打開地圖頁就有。

好友那邊分享 `https://你的網域/` 就好，地圖是公開的。

## 日記怎麼長出來

地圖頁上方有一排日期。日期軸分段呈現，60 天列成 60 顆膠囊沒人滑得動。有兩種切法，點「依縣市／依週」那顆隨時切換，選擇記在瀏覽器裡：

- **依縣市**（預設）——環島本來就是一段一段的縣市，看得出「走到哪裡了」。跨縣市的那天用**當天最後一筆**的位置歸段：他今天走到哪裡就算哪裡。（原本用「當天出現最多次」的縣市，結果走了一天臺南、傍晚進嘉義，嘉義整個被吃掉。）「臺」「台」混用視為同一縣市。
- **依週**——第 1 週、第 2 週，看得出「走多久了」，節奏比較均勻。

每一段顯示天數／日期範圍和公里數，點下去看那幾天；選中的段會展開該段的逐日膠囊。

點「第 8 天」就只看那天：地圖縮到那天的路段，其餘路線淡淡留著當底圖；下面是那天的完整記錄——從哪走到哪、直線幾公里、幾次打卡、幾張照片，接著是逐筆的時間軸和照片。點「全程」看整趟。

**換一個地瓜**　地圖左下角有四顆小圓，切換目前位置的標記形象：手繪頭像、番薯（台灣本來就是番薯島）、颱風（環島就是繞著轉一圈）、一個人在跑。選擇記在各自的瀏覽器裡，好友各看各的，互不影響。

**每天一個顏色**　路線逐日上色，八色循環（深綠、磚紅、靛藍、土黃、紫、藍綠、酒紅、橄欖）。相鄰的日子一定差很多，看得出哪裡換日；同色要隔八天才重複，那時已經走到島的另一邊，不會誤認。日期膠囊和日記區塊的左側色條用同一個顏色，三處對得起來。

隔夜的接續用灰色細虛線帶過，不假裝是連續走的。滑過線段會顯示「第 N 天　28.5 km」。

最左邊還有一顆「照片」，切過去是整面的照片牆——三欄方格、依天分組、由新到舊，一眼掃完整趟。牆上載的是 400px 縮圖，點開才抓大圖，所以照片再多也不會拖垮手機流量。

網址會跟著變：某一天是 `#d8`、某段縣市是 `#leg:台東縣-21`、全程是 `#all`、照片牆是 `#photos`、留言板是 `#board`，都可以直接傳給人。照片點一下放大，Esc 或再點一下關掉。

**收工那筆的留言，就是當天的日記。** 這是唯一要跟地瓜講的規則：路上按「打卡」隨手拍照寫短句，晚上按「收工」時在留言欄寫比較完整的一段，那段會用米黃色的框顯示在當天的最上面，其他打卡的短句留在時間軸裡。這樣他不用另外經營一個地方，走完就是一本日記。

## 打卡頁的計時器

頂端是一個秒級計時器，開著就一直跳。左上角有狀態標示，圓點會呼吸閃動，三種狀態：

- **步行中**（綠）— 顯示今天累計步行時間
- **休息中**（灰藍）— 改成顯示這段休息多久了，走路時間凍結，旁邊小字寫「今天已走 5 小時 42 分」
- **今天收工了**（黑）— 停在最終時數

同一組標示也出現在公開地圖的「地瓜現在在」旁邊，好友一眼就知道他此刻在走還是在休息。

計時器的狀態有兩個來源：打卡當下伺服器回的數字，以及每次開 App、切回前景時主動跟伺服器對一次。只靠前者不夠——訊號不穩時回應可能在路上掉了，重送時伺服器只認得出「這筆重複了」，早期版本那條路徑不會帶回今日狀態，計時器就會卡在「尚未出發」。現在重複送出也會回傳完整狀態，加上主動同步，兩道保險。

計時只在畫面亮著時跳，切到背景就停，不耗電。時間基準是伺服器算的，所以中途換手機、清快取都不會跑掉。

## 休息日

兩個月的旅程大概會有八到十天不走。原本這些日子在網站上是空白的——沒按出發就沒有任何點，日期軸直接跳過去。但休息日往往才有故事：住哪裡、吃什麼、遇到誰。

按「今天休息」之後，那天標成休息日：不計時、不算里程，但照樣可以打卡拍照。日記上顯示成「休息日 · 照片 N 張」，配土黃色調，跟走路的日子在視覺上分開。「今天休息」那筆的留言就是當天的日記，跟收工的規則一致。

里程牌的天數拆成「走 N 天 · 休 M 天」。

刻意不做「美食／風景」之類的分類——那要他每次打卡都想一下歸哪類，是持續的認知成本，走到第三十天一定放棄。休息日一天按一次，而且那天他本來就閒著。照片自然就是吃飯旅遊的紀錄。

## 時區

分日一律用台北時間（`Asia/Taipei`），不看瀏覽器所在時區。原本用本地時間，好友在國外看會整個錯開——台灣早上六點的打卡，在美西會被算成前一天，日期軸就分裂了。日期、時間的顯示也都指定了時區。

## 今日目標

按「出發」時可以用兩層下拉選單設定今天要走到哪：先選縣市、再選鄉鎮市區。

縣市清單的順序是**目前所在 → 相鄰縣市 → 其他**，所以他多半只要點第一或第二個。所在縣市由上一次打卡的地址推出來，預設就選好了。可以留空。

資料在 `tw.js`，本島 19 個縣市、352 個鄉鎮市區，加上相鄰關係表（寫完有做對稱性驗證）。這個檔案有進 Service Worker 的快取清單，沒訊號也選得出來。

目標會寫進試算表的「今日目標」欄、出現在日記那天的統計列、也會放進出發那封信裡。當天最後一筆的位置如果對得上目標，日記上會標「達成」。

## 數字

日期軸最左邊的「數字」，走到一半也看得到的統計。走完之後這一頁就是回顧的骨架。

四個大數字：**總天數**（拆成走幾天、休幾天）、**累計距離**、**經過的縣市**、**沿路的照片**。下面列出走過的縣市，再下面是「之最」——走最遠的一天、在路上最久的一天、最熱的一天、最涼的一天、拍最多照片的一天。每一則點下去會跳到那一天的日記。

溫度取自各筆打卡的天氣欄，取當天的最高／最低。休息日不列入「走最遠」和「在路上最久」。

## 按讚

每一天和每一張照片都可以按讚，不用留名字。按下去立刻變色、數字馬上跳，才送出到伺服器——網路慢的時候不會覺得沒反應。再按一次收回。

訪客身分是瀏覽器自己產生的一組 id，存在他自己的 localStorage 裡。這擋得住同一個人重複按，但擋不了有心人換瀏覽器洗票。這是刻意的取捨：要擋就得要求登入，而登入會讓九成的好友直接放棄。

讚存在「讚」分頁，一列一次。要作廢哪一筆，把「狀態」從「有效」改掉即可。

照片縮圖右下角同時顯示讚數和留言數。

## 留言板

地圖頁日期軸最左邊的「留言」，好友可以留話給地瓜，不用註冊、不用 Email，填名字和內容就好。名字會記在瀏覽器裡，下次自動帶入。

**地瓜怎麼看到**　他每次打卡送出後，如果上一次打卡之後有新留言，畫面會自動彈出來給他看。不用他主動去翻，也不會漏掉。

**當天的留言**　留言板上的留言，也會依「留言時間」出現在日記中對應那一天的最下面，標成「當天的留言 N 則」。所以往回翻某一天，看得到那天走的路、拍的照片，以及當天大家說了什麼。留言板那一頁仍然是完整清單。

留言在沒有打卡紀錄的日子（例如還沒出發前）不會出現在日記裡，但留言板一定看得到。

**照片留言**　點開任何一張照片，下面就能留言，地瓜自己也可以（用同一個地圖頁，填名字就好）。有留言的照片右下角會顯示數量。

留言掛在 Drive 的檔案 id 上，所以照片不會跟留言脫鉤。

**管理**　留言存在試算表的「留言」分頁，「對象」欄空白的是留言板，`photo:xxx` 的是掛在照片下。想隱藏哪一則，把該列的「狀態」欄從「顯示」改成別的字就好，下次重整就不見了。

程式有擋重複送出（同一個人兩分鐘內貼一樣的內容），名字上限 20 字、內容上限 300 字。但這是公開的寫入端點，還是留意一下有沒有人亂留。

## 打卡頁的天氣與補水提醒

計時器下方是一條天氣列，顯示他所在位置的氣溫、天氣，體感和實測差兩度以上時也一起顯示。提醒文字依體感溫度變色分級：

| 體感 | 邊條顏色 | 提醒 |
|---|---|---|
| 34°C 以上 | 紅 | 每 15–20 分鐘喝水，並列出中暑的早期徵兆 |
| 30–34°C | 黃 | 每 20–30 分鐘補水，中午走有遮蔭的一側 |
| 下雨 | 灰藍 | 路滑；涼天一樣會脫水 |
| 14°C 以下 | 灰藍 | 冷天照樣補水，休息時別穿著汗濕衣服吹風 |
| 其他 | 灰 | 每 30 分鐘喝一次水 |

資料一樣來自 Open-Meteo，由手機直接抓，不經過後端。開 App 時更新一次，之後每 15 分鐘一次，打卡送出後也會用新座標重抓。抓不到就整條隱藏，不影響打卡。

第一次使用時因為還沒有座標，天氣列不會出現；打完第一次卡之後就會一直有。

## 時數怎麼算

從當天第一筆打卡算到「收工」（還沒收工就算到現在）。這是**在路上的總時長**，不是純步行時間。

曾經有「休息」按鈕用來暫停計時，實測發現走了一天的人不可能記得按——一個要靠使用者自律才正確的數字，一定會失準。所以改成誠實顯示「在路上 8 小時 20 分」，這個數字不需要他做任何事就永遠對。

後端的 `TYPES` 裡「休息」還留著（標記為停用），扣除邏輯也保留，舊資料讀得出來，哪天想加回來只要把它排進按鈕就好。

## 天氣

每次打卡都會抓當下位置的氣溫、體感和天氣狀況，存進試算表，也顯示在地圖的日記裡和信件主旨上。

資料來自 Open-Meteo，免金鑰、免註冊。抓不到就留空，絕對不會擋住打卡。

## 幾個要先知道的事

**寄信額度**　一般 Gmail 帳號一天 100 封，Workspace 1500 封。算法是：選「出發和收工」的人數 × 2，加上選「每次打卡都要」的人數 × 當天打卡次數。後者很吃額度——十個人選全部、一天打卡八次就是 80 封。額度不足時系統會跳過該次通知，不會整個爆掉。

**實走里程優先**　收工時可以填「今天實際走了幾公里」，填了就以他填的為準，地圖上會標「（實走）」。打卡點之間推算的距離只是備援——他真正走的路一定比打卡點連線長。

數字存在「每日里程」分頁，格式是 `2026-09-05` 和公里數兩欄。事後要更正、或補填之前沒填的日子，直接在那個分頁加列或改數字就好，不用重新打卡。總里程也會跟著用實走值重算。

**當日第一筆不算距離**　前一筆是昨天收工的地方，中間隔了一夜——他可能住宿、搭車移動過，那段路不是今天走的。所以每天第一筆的距離一律是 0，試算表的「距離來源」會記「當日首筆」。輸出給網站時也會把舊資料每天第一筆的距離歸零，歷史數字一併修正，不用改試算表。

**距離怎麼算（沒填實走時的備援）**　每次打卡時，用 Maps 服務查上一點到這一點的**步行路線**距離，當下算好寫進試算表，之後不重算。跨海、無路可達或額度用完時退回直線距離，試算表的「距離來源」欄會標明是哪一種。

準確度大致落在實際里程的九成以上，剩下的誤差來自系統挑的是最短路線，未必是他真的走的那條。打卡次數越多越準——一天只按「出發」和「收工」兩次的話，中間繞的路全部吃掉。

Maps 服務免費額度是一天 1000 次查詢，一天打卡十次也用不到 1%。

**照片**　一次打卡最多 8 張，長邊壓到 1280px。

從別人那裡收到、存進相簿的原始大圖（例如 LINE 傳來的 4000×3000）會把 iOS 的記憶體吃爆，分頁被回收就變成「App 跳掉」。兩個對策：用 `createImageBitmap` 在解碼當下就縮小，記憶體差一個數量級；多張時一張一張依序處理，不並行。

另外打卡草稿（類型、留言、里程、已選照片）會即時存進 localStorage，就算頁面真的被系統回收，重開會自動接回來，不用重按。兩小時後的草稿自動作廢。

選好會出現縮圖列，點縮圖右上角的 × 可以拿掉。試算表的「照片ID」和「照片網址」欄用逗號串起多筆，舊的單張資料照樣讀得到，不用改欄位。

**沒訊號**　打卡會先存在手機裡，回到有網路時自動補送，畫面下方會顯示「還有 N 筆等訊號」。同一筆有唯一 ID，補送不會重複記錄。手機空間不足時會先丟照片保住位置紀錄。

**照片權限**　照片存在該帳號 Drive 的「陳地瓜走到哪 照片」資料夾，每張自動設成「知道連結的人可以看」。Workspace 帳號若被管理員關掉對外分享，照片會存進去但顯示不出來——這也是要用另開的免費 Gmail 帳號跑的原因之一。

**隱私**　地圖是公開的，等於公開陳地瓜的即時位置。出發前跟他確認過。系統做了兩道鈍化：

- `ADDR_LEVEL: 'district'` — 地址只到鄉鎮市區（「台南市中西區」），不顯示路名門牌。改成 `'road'` 會多帶路名但仍不含號碼，`'full'` 則是完整地址。
- `PUBLIC_PRECISION: 3` — 對外公開的座標只到小數第 3 位，約 110 公尺。試算表裡仍存精確座標（距離計算需要），只有地圖變粗。改成 2 約 1.1 公里。

照片經過 canvas 重新編碼，EXIF 全部剝除，不會外洩原始拍攝座標。

系統不記錄任何人的 IP。訂閱者的 Email 只存在試算表；目前「退訂」是把狀態改成「已退訂」而非刪除，若有人要求刪除資料要手動刪那一列。真的介意的話，最小改動是把地圖頁也加通行碼，公開的只留每日摘要。

**電池**　打卡頁只在按下按鈕時取一次定位，不做背景追蹤（手機瀏覽器也做不到）。這是刻意的，不然一天走不到中午就沒電。
