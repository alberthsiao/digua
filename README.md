# 陳地瓜走到哪 R1.8

陳地瓜徒步環島的打卡與通知系統。

前端靜態網頁（GitHub Pages）＋ 後端 Google Apps Script（試算表、Drive、寄信）。

```
web/  → 丟到 GitHub Pages / Cloudflare Pages
  index.html      公開地圖＋日記，任何人都能看
  digua.png / og.jpg / icon-*.png   頭像、分享預覽圖、PWA 圖示（與 html 同層，不放子資料夾）
  checkin.html    打卡頁，網址帶通行碼，只給環島的朋友
  subscribe.html  訂閱與退訂
  manifest.json / sw.js / icons/   加到主畫面用

gas/
  程式碼.gs        貼進 Apps Script
```

## 為什麼前端不放在 Apps Script 裡

Apps Script 的網頁應用程式是包在跨網域 iframe 裡送出來的，而 `navigator.geolocation` 在跨網域 iframe 需要外層加上 `allow="geolocation"`——那個 iframe 是 Google 產生的，我們改不到。這個限制自 Chrome 63 起生效，Google 的功能請求（issue 68032861）至今未實作。

所以定位頁必須是頂層文件。順帶好處：可以裝 Service Worker、可以做 PWA、可以綁自己的網域。Apps Script 專心當 API 就好。

## 一、後端（約 10 分鐘）

1. 用**專門開的那個 Google 帳號**建一個新試算表，命名「陳地瓜走到哪」。
2. 選單 **擴充功能 → Apps Script**，把 `gas/程式碼.gs` 全部貼進去，覆蓋原本的內容。
3. 改最上面的 `CONFIG`：

   | 欄位 | 說明 |
   |---|---|
   | `CHECKIN_TOKEN` | 一組長亂碼，等一下會出現在打卡頁網址列 |
   | `SITE_URL` | 前端網址，**結尾不要斜線** |
   | `WALKER_NAME` | 已填「陳地瓜」 |
   | `SITE_NAME` | 已填「陳地瓜走到哪」，寄件者名稱與信件抬頭都用它 |
   | `START_DATE` | 出發日，用來算「第幾天」 |

4. 執行一次 `setup()`，授權所有權限（會要求 Drive、Gmail、地圖）。這一步會建好兩個分頁和照片資料夾。
5. 執行一次 `testMail()`，確認信寄得出去。
6. **部署 → 新增部署作業 → 網頁應用程式**
   - 執行身分：**我**
   - 誰可以存取：**所有人**
   - 複製出來的 `.../exec` 網址。
7. 之後每次改 `程式碼.gs`，都要**部署 → 管理部署作業 → 編輯 → 版本選「新版本」**，不然線上跑的還是舊的。

## 二、前端（約 5 分鐘）

1. 把 `web/` 三個 html 檔最上面的 `API_URL` 換成剛剛那個 `.../exec` 網址。
2. `checkin.html` 裡的 `START` 出發日要跟後端 `CONFIG.START_DATE` 一致。
3. 建一個 GitHub repo，把 `web/` 底下的東西放進去（注意是內容，不是資料夾本身），Settings → Pages → 來源選 main 分支根目錄。
4. 記得回頭把後端的 `SITE_URL` 改成實際網址，重新部署新版本。

## 三、交給環島的朋友

傳這個網址給地瓜，只傳給他一個人：

```
https://你的網域/checkin.html?t=你設定的CHECKIN_TOKEN
```

請他用 Safari 或 Chrome 開啟，**加入主畫面**。通行碼會存在裝置裡，之後從主畫面點開就直接能打卡。

第一次按任何一顆按鈕時，手機會問要不要允許定位——一定要選「允許」。

三顆按鈕：

| 按鈕 | 會寄信嗎 | 什麼時候按 |
|---|---|---|
| 出發 | 所有訂閱者 | 開始計時。**休息結束也按這顆**，計時才會繼續 |
| 休息 | 只有選「每次打卡都要」的人 | 停下來吃飯、躲雨。這段時間不算步行 |
| 打卡 | 只有選「每次打卡都要」的人 | 純紀錄，拍照寫短句，**不影響計時** |
| 收工 | 所有訂閱者 | 今天走完了，留言欄那段就是當天日記 |

版面排成：第一行「出發｜休息」並排，第二行「打卡」，第三行「收工」。

當天第二次以後按「出發」會被視為「繼續走」，只寄給選「每次打卡都要」的人，不會每次休息完就吵到所有好友。

訂閱時可選兩種：**每次打卡都要**（一天五到十封，預設）或**出發和收工就好**（一天兩封）。沒有每日摘要信，想看細節打開地圖頁就有。

好友那邊分享 `https://你的網域/` 就好，地圖是公開的。

## 日記怎麼長出來

地圖頁上方有一排日期。點「第 8 天」就只看那天：地圖縮到那天的路段，其餘路線淡淡留著當底圖；下面是那天的完整記錄——從哪走到哪、直線幾公里、幾次打卡、幾張照片，接著是逐筆的時間軸和照片。點「全程」看整趟。

最左邊還有一顆「照片」，切過去是整面的照片牆——三欄方格、依天分組、由新到舊，一眼掃完整趟。牆上載的是 400px 縮圖，點開才抓大圖，所以照片再多也不會拖垮手機流量。

網址會跟著變：某一天是 `#d8`、全程是 `#all`、照片牆是 `#photos`，都可以直接傳給人。照片點一下放大，Esc 或再點一下關掉。

**收工那筆的留言，就是當天的日記。** 這是唯一要跟地瓜講的規則：路上按「打卡」隨手拍照寫短句，晚上按「收工」時在留言欄寫比較完整的一段，那段會用米黃色的框顯示在當天的最上面，其他打卡的短句留在時間軸裡。這樣他不用另外經營一個地方，走完就是一本日記。

## 打卡頁的計時器

頂端是一個秒級計時器，開著就一直跳。左上角有狀態標示，圓點會呼吸閃動，三種狀態：

- **步行中**（綠）— 顯示今天累計步行時間
- **休息中**（灰藍）— 改成顯示這段休息多久了，走路時間凍結，旁邊小字寫「今天已走 5 小時 42 分」
- **今天收工了**（黑）— 停在最終時數

同一組標示也出現在公開地圖的「地瓜現在在」旁邊，好友一眼就知道他此刻在走還是在休息。

計時只在畫面亮著時跳，切到背景就停，不耗電。時間基準是伺服器算的，所以中途換手機、清快取都不會跑掉。

## 打卡頁的天氣與補水提醒

計時器下方是一條天氣列，顯示他所在位置的氣溫、天氣，體感和實測差兩度以上時也一起顯示。提醒文字依體感溫度變色分級：

| 體感 | 邊條顏色 | 提醒 |
|---|---|---|
| 34°C 以上 | 紅 | 每 15–20 分鐘喝水，並列出中暑的早期徵兆 |
| 30–34°C | 黃 | 每 20–30 分鐘補水，中午走有遮蔭的一側 |
| 下雨 | 灰藍 | 路滑；涼天一樣會脫水 |
| 14°C 以下 | 灰藍 | 冷天照樣補水，休息時別穿著汗濕衣服吹風 |
| 其他 | 灰 | 每 30 分鐘喝一次水 |

資料一樣來自 Open-Meteo，由手機直接抓，不經過後端。開 App 時更新一次，之後每 15 分鐘一次，打卡送出後也會用新座標重抓。抓不到就整條隱藏，不影響打卡。

第一次使用時因為還沒有座標，天氣列不會出現；打完第一次卡之後就會一直有。

## 行走時數怎麼算

從當天第一筆打卡算到「收工」（還沒收工就算到現在），扣掉每一段休息。

**休息從按下那一刻開始，到下一次按「出發」或「收工」為止。**中間按「打卡」不會恢復計時——所以他休息時拍便當、拍風景都不會誤判成又在走了。

如果他休息後忘了按「出發」，那段會一路算到收工。打卡頁頂端會顯示灰藍色的「休息中」標示和「按『出發』繼續計時」，開 App 就看得到，是刻意設計成看得見而不是自動猜。

## 天氣

每次打卡都會抓當下位置的氣溫、體感和天氣狀況，存進試算表，也顯示在地圖的日記裡和信件主旨上。

資料來自 Open-Meteo，免金鑰、免註冊。抓不到就留空，絕對不會擋住打卡。

## 幾個要先知道的事

**寄信額度**　一般 Gmail 帳號一天 100 封，Workspace 1500 封。算法是：選「出發和收工」的人數 × 2，加上選「每次打卡都要」的人數 × 當天打卡次數。後者很吃額度——十個人選全部、一天打卡八次就是 80 封。額度不足時系統會跳過該次通知，不會整個爆掉。

**距離怎麼算**　每次打卡時，用 Maps 服務查上一點到這一點的**步行路線**距離，當下算好寫進試算表，之後不重算。跨海、無路可達或額度用完時退回直線距離，試算表的「距離來源」欄會標明是哪一種。

準確度大致落在實際里程的九成以上，剩下的誤差來自系統挑的是最短路線，未必是他真的走的那條。打卡次數越多越準——一天只按「出發」和「收工」兩次的話，中間繞的路全部吃掉。

Maps 服務免費額度是一天 1000 次查詢，一天打卡十次也用不到 1%。

**沒訊號**　打卡會先存在手機裡，回到有網路時自動補送，畫面下方會顯示「還有 N 筆等訊號」。同一筆有唯一 ID，補送不會重複記錄。手機空間不足時會先丟照片保住位置紀錄。

**照片權限**　照片存在該帳號 Drive 的「陳地瓜走到哪 照片」資料夾，每張自動設成「知道連結的人可以看」。Workspace 帳號若被管理員關掉對外分享，照片會存進去但顯示不出來——這也是要用另開的免費 Gmail 帳號跑的原因之一。

**隱私**　地圖是公開的，等於公開陳地瓜的即時位置。出發前跟他確認過。真的介意的話，最小改動是把地圖頁也加通行碼，公開的只留每日摘要。

**電池**　打卡頁只在按下按鈕時取一次定位，不做背景追蹤（手機瀏覽器也做不到）。這是刻意的，不然一天走不到中午就沒電。
